# DevNote v0.5.1 — Manual E2E Test Checklist

This checklist gates the v0.5.1 commit. Per the **verify-before-commit** rule established in prior memory (see `feedback_verify_before_commit.md`), Marudhu walks every item below against the built `.vsix` in a fresh VS Code instance **before Task 12 dispatches the single final commit**. v0.5.1 is a UX overhaul on top of v0.5.0's chat surface — the marked.js bug is the first-priority verification because v0.5.0 shipped with broken markdown rendering. Open side-by-side during testing. Check off as verified. ~50 checks, estimated ~45-60 minutes.

Design-decision verification map: D22 (tab navigation, reverses D16) §2 · D23 (stop button) §4 · D24 (suggested questions) §3 · D25 (3-stage loading) §5 · D26 (visual polish) §7 · marked.js bug fix §1.

## 1. Bug fix verification (most important)

The v0.5.0 ship had a 403 on `marked.min.js` that blocked rendering — citation pills stayed as raw `[Note 1]` text and bold/italic/lists never rendered. This section verifies the fix landed.

- [ ] Trigger a chat with a question whose answer involves bold, italic, lists, and code → answer renders with proper bold, italic, bulleted/numbered lists, and code blocks
- [ ] `[Note 1]` references in the answer show as **clickable pills**, not as plain `[Note 1]` text
- [ ] Open VS Code DevTools Console while chatting → **NO 403 error** for `marked.min.js` (or any other webview asset)
- [ ] Right-click an assistant bubble → Inspect → confirm `<a class="citation-pill">` elements are present in the DOM (not literal `[Note N]` text nodes)
- [ ] Reload the sidebar webview → markdown rendering still works on subsequent answers (not a one-shot fix)

## 2. Tab navigation (D22 verification — reverses D16)

D22 reverses v0.5.0's D16 mode-coexistence pattern in favor of explicit tabs. If tab navigation works end-to-end, D16 is successfully reversed.

- [ ] Sidebar opens with **Home tab active by default** (🏠 Home button highlighted with active styling)
- [ ] Click 💬 Chat tab → switches to chat view; tab bar shows 💬 Chat highlighted, 🏠 Home un-highlighted
- [ ] Click 🏠 Home tab → switches back to Home view; search input + Recent Notes list intact (v0.4.x Idle behavior preserved)
- [ ] ← back button in chat header returns to Home tab (same effect as clicking 🏠 Home)
- [ ] Sidebar collapse-expand within the same VS Code session: **tab state preserved** (if you were on Chat, you return to Chat)
- [ ] Tab switching never throws a console error or leaves stale UI from the other tab

## 3. Suggested questions (D24 verification)

- [ ] On first Chat-tab open (empty thread): **4 suggestion buttons visible**, vertically stacked
- [ ] Click any suggestion → fills the chat input with that text **and auto-sends** (no second click needed)
- [ ] After conversation starts (≥1 message exchanged): empty state hides; chat bubbles appear in its place
- [ ] Click "New chat" → conversation clears; **empty state reappears with the same 4 suggestions**
- [ ] Suggestions render cleanly on narrow sidebar widths (no overflow, no clipping)

## 4. Stop button (D23 verification)

- [ ] Send a query → Send button (⏎) **hides**, Stop button (■) becomes visible in its place
- [ ] Click Stop mid-stream → assistant bubble **freezes at current text** (partial answer preserved, NOT cleared)
- [ ] After Stop: Stop button hides, Send button restores in the input area
- [ ] Send a second query immediately after a stop → works normally (new stream id, no collision with the stale stopped stream)
- [ ] Stop on a fast/short answer that completes before you click → no error, button just transitions back to Send

---

## 5. 3-stage loading (D25 verification)

- [ ] On send, bubble shows "**Searching your notes...**" during retrieval (italic / dashed-border style)
- [ ] Brief flash of "**Found N notes...**" between retrieval and generation (singular "1 note" for one result, plural "N notes" for >1)
- [ ] "**Generating answer...**" appears between retrieval-done and the first streamed token
- [ ] On first token: loading-state styling (italic / dashed border) **strips off** and raw text streams normally
- [ ] Refusal path also goes through the 3 stages cleanly (no stuck loading state on a no-context answer)

- [ ] Long answers scroll cleanly within the transcript area; chat header (← back, "New chat") stays pinned at top
- [ ] Resizing sidebar width does not break input stickiness or header pinning
