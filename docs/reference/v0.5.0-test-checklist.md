# DevNote v0.5.0 — Manual E2E Test Checklist

This checklist gates the v0.5.0 commit. Per the **verify-before-commit** rule established in prior memory, Marudhu walks every item below against the built `.vsix` in a fresh VS Code instance **before Task 15 commits**. Open side-by-side during testing. Check off as verified. ~55 checks, estimated ~60-75 minutes (chat path is the first conversational shipping surface, so testing is qualitative-heavy).

Design-decision verification map: D15 (model fallback) §7 · D16 (mode coexistence) §8 · D17 (citations) §4 · D18 (persistence) §9 · D19 (multi-turn) §5 · D20 (markdown rendering) §10 · D21 (refusal) §6.

---

## 1. Setup / Upgrade

### Fresh install (no prior DevNote)

- [ ] Install v0.5.0 from `.vsix` on a machine with no prior DevNote
- [ ] Sidebar opens, setup wizard appears (same as v0.4.x)
- [ ] After credentials saved, Idle state shows Generate Doc + Recent Notes + 🔍 search input + 💬 chat input
- [ ] No Python popups on activation (chat is lazy, same pattern as search)

### Upgrade from v0.4.2

- [ ] Credentials carry over automatically (no re-entry)
- [ ] All existing v0.4.x notes still visible in Recent Notes list
- [ ] `devnote.db` preserved — schema_version stays compatible, existing embeddings intact
- [ ] No "fresh setup" popup on activation — venv reused if previously initialized
- [ ] Search continues to work without re-indexing (warm path preserved)

### Empty MemoryStore guard

- [ ] On a fresh install with 0 notes, chat input is **disabled** (greyed-out)
- [ ] Disabled chat input shows empty-state hint: "Save a note first to chat with your memory."
- [ ] Search input also reflects 0-notes state (existing v0.4.x behavior preserved)
- [ ] After saving the first note, chat input becomes enabled

## 2. First chat (cold path — no Python yet)

### Python missing

- [ ] On a machine WITHOUT Python, click chat input + send → popup: "DevNote needs Python 3.10+ [Install Guide]"
- [ ] Cancel popup → chat gracefully disabled, no error state, no broken bubble
- [ ] Install Python 3.11, retry chat → setup flow proceeds (same as search cold path)

### Venv setup on first chat

- [ ] First chat on valid Python (no venv yet) → "Setting up Python environment (~30s)..." progress notification
- [ ] After venv setup completes, the in-flight chat message proceeds automatically (no double-send needed)
- [ ] `globalState.venvReady = true` after successful setup

### Backfill on first chat

- [ ] Notes with NULL embeddings present → first chat triggers backfill popup: "Indexing your {N} past notes for chat (~{T}s)..."
- [ ] Backfill runs via Gemini batch API, all `embedding` columns populated
- [ ] After backfill, the chat answer streams without a second wait

### Cold path completion

- [ ] After all setup popups complete, the original chat question is answered (not silently dropped)
- [ ] Subsequent chats have ZERO setup popups — straight to streaming

## 3. First chat (warm path — search has been used)

- [ ] Send question → first token (TTFT) appears within ~500ms
- [ ] Streaming text appears typewriter-style (raw characters, not buffered)
- [ ] Stream completes → final markdown rendering swaps in atomically
- [ ] Citation pills appear inline next to the rendered answer
- [ ] Total roundtrip for a normal question feels <3s on a warm worker

## 4. Citations (D17 verification)

- [ ] Pill click opens the cited source note in inline preview
- [ ] Preview shows note title + branch + date + "Open in Notion" full-width button
- [ ] Back from preview returns to chat with **conversation intact** (not reset)
- [ ] An invalid `[Note 7]` reference in the model output (when k=5) renders as **plain text**, not a clickable pill
- [ ] Multiple pills in the same answer are all individually clickable, each opening the right note
- [ ] Pill hover state styled distinctly from regular text

---

## 5. Multi-turn (D19 verification)

- [ ] Turn 1: ask about a project. Turn 2: ask "when was that?" → pronoun resolves correctly using prior context
- [ ] After 6+ turns, only the **last 4 history entries** are in the prompt sent to Gemini (verify via worker stdout if `DEBUG=1`)
- [ ] Turn N+1 still cites notes from the retrieval, not from prior turn memory alone
- [ ] Topic pivot ("what's the weather today") with no relevant notes hits refusal path (see §6)
- [ ] Conversation thread visually scrollable; older turns stay readable

---

## 6. Refusal path (D21 verification, anti-hallucination)

- [ ] Ask a question with no relevant notes → model returns: "I don't find that in your notes." (or close variant)
- [ ] Refusal answer contains **zero citation pills** (no fabricated `[Note N]` references)
- [ ] Refusal still appears as a chat bubble (not an error toast)
- [ ] User can ask a follow-up after a refusal without the chat resetting

---

## 7. Error handling (D15 verification on fallback)

- [ ] Force-kill the Python worker mid-stream → toast: "Chat worker restarted. Retry?" → retry resends the question
- [ ] Network offline during chat → empty state in chat: "Chat requires internet. You're offline."
- [ ] Simulate Gemini Flash 503 (block its endpoint) → chat **silently falls back to flash-lite** → answer still streams (verify model name in worker stdout)
- [ ] Simulate **both** Flash AND Flash-Lite failing → clear error toast: "Chat models unavailable. Try again in a moment."
- [ ] After both-fail toast, user can retry; transient failures recover on next attempt

---

## 8. Mode coexistence (D16 verification)

- [ ] Idle state: search input + chat input + Recent Notes list **all visible simultaneously**
- [ ] Type in search input → search mode active, chat input remains visible but Recent Notes hides under search results
- [ ] Type in chat input → chat mode active, search results / Recent Notes hide, chat thread shows
- [ ] ✕ on search → returns to Recent Notes (chat input still visible & functional)
- [ ] "New chat" / clear on chat → returns to Recent Notes (search input still visible & functional)
- [ ] Both inputs empty → Recent Notes visible (default Idle)
- [ ] Switching between modes never throws a console error or leaves stale UI

---

## 9. Persistence (D18 verification)

- [ ] Send 2-3 chat messages → collapse the sidebar → expand again → chat thread still visible (in-session persist)
- [ ] Switch sidebar tab away and back → chat thread still visible
- [ ] Close & reopen VS Code → chat thread is **empty** (no cross-session persistence by design)
- [ ] Click "New chat" button → conversation clears immediately, input refocused
- [ ] Reload VS Code window mid-stream → chat resets cleanly (no zombie streaming bubble, no orphan worker process)

---

## 10. Markdown rendering (D20 verification)

- [ ] During stream, raw `**bold**`, `[Note 1]`, `*italic*` text visible character-by-character (typewriter)
- [ ] On stream complete, raw text **swaps atomically** to: rendered bold, rendered italic, clickable pills
- [ ] Bulleted lists render with bullets after stream completes
- [ ] Numbered lists render with numbers after stream completes
- [ ] Code blocks render in monospace with proper background after stream completes
- [ ] **Cosmetic check:** the typewriter raw-text feel during stream is acceptable (D20 known risk — if it feels jarring, file a v0.6+ progressive-rendering issue, do **not** block v0.5.0)

## 12. Pre-launch quality checks (light eval)

This is a qualitative pass before ship. Aim for **4-of-5 acceptable answers**. Hallucination risk is real (Lesson 6 / Lesson 7) — this gate matters more than any automated test.

- [ ] Test 1 — ask a real question about your own notes. Was the answer correct? Citation valid? Would you trust it?
- [ ] Test 2 — different note, different domain (e.g. a debugging note vs a meeting note). Same three checks.
- [ ] Test 3 — multi-note synthesis question (something that needs 2-3 notes combined). Did it pull the right notes? Did it stitch them coherently?
- [ ] Test 4 — follow-up question building on Test 3 (multi-turn). Did it use prior turn correctly?
- [ ] Test 5 — clearly-impossible question (something definitely not in your notes). Confirm refusal works, no hallucinated citations.
- [ ] Overall: at least 4 of these 5 felt acceptable to ship to a friend. If <4, **do not commit**; file issues and iterate.
