# DevNote v0.5.1 — UX Overhaul + Markdown Bug Fix Design Spec

**Date:** 2026-04-27
**Status:** Draft (pending approval)
**Scope:** v0.5.1 — UX polish + critical bug fix on top of v0.5.0 RAG Chat

---

## One-line summary

Reverse D16 (stacked-input mode-toggle) in favor of a dedicated 2-tab sidebar (🏠 Home + 💬 Chat) with full-height chat, sticky bottom input, back button, stop button, 3-stage loading state, and a hardcoded suggested-questions empty state. Plus fixes the v0.5.0 production bug where `marked.min.js` failed with HTTP 403, leaving markdown un-rendered in chat answers.

---

## Why this release exists

v0.5.0 shipped on 2026-04-26 and into the user's hands. Two days of dogfooding produced two clear signals:

1. **Real UX gap:** the stacked-input pattern from D16 felt cramped; chat didn't feel like a "real chat product." Users with ChatGPT/Claude/Cursor muscle memory expected a dedicated chat surface with sticky input, full height, and a way to stop the AI mid-stream.
2. **Real bug:** `marked.min.js` returned 403 inside the webview because Task 11 added the script tag without going through `webview.asWebviewUri(...)`. Markdown in chat answers silently rendered as raw text with `**asterisks**` and unclickable `[Note 1]` markers.

v0.5.1 is the polish + fix release that closes both.

### How chat lifecycle messages flow

```
User clicks "Searching..." → SidebarProvider posts:
  → chat-retrieving
  ↓
ChatService.askQuestion() runs:
  • ensureReady, searchQuery, getNotesByIds  → SidebarProvider posts:
    → chat-retrieved (with note count N)
  • buildPrompt                              → SidebarProvider posts:
    → chat-generating
  • bridge.callStream(...)                   → emits chat-token (existing)
                                             → on done emits chat-done (existing)
```

Webview shows the staged labels in the assistant bubble until the first `chat-token` arrives, at which point it switches to streaming raw text.

### Stop button state machine

Three states for the chat input row:

```
IDLE       → [💬 Ask your memory...]  [⏎ Send (disabled if empty)]
SUBMITTED  → [💬 Ask your memory...]  [⏎ Send (disabled)]
STREAMING  → [💬 Ask your memory...]  [■ Stop]
```

Transitions:
- `IDLE → SUBMITTED` on send button click (or Enter)
- `SUBMITTED → STREAMING` on first `chat-token` OR `chat-generating` message
- `STREAMING → IDLE` on `chat-done` OR user clicks Stop OR `chat-error`

When user clicks Stop:
- TS sets `currentStreamId = null`
- Subsequent `chat-token` for the dropped stream id are discarded
- Assistant bubble keeps its current text (unrendered — citation pill swap is skipped for stopped streams; the `[Note N]` markers stay as plain text)
- Send button is restored
- Python worker continues to `done` naturally; the result is silently dropped

### Suggested questions

Hardcoded list (configurable in JS, since they're static):

```javascript
const SUGGESTED_QUESTIONS = [
  "What did I do last week?",
  "Show recent OAuth work",
  "Summarize my April notes",
  "What did I fix in the last session?",
];
```

Rendered as buttons inside the chat empty state. Click → fills `chatInput.value` + submits via the same path as a manual send.

## Bug fix detail — marked.js 403

**Root cause:** v0.5.0 Task 11 added `<script nonce="{{NONCE}}" src="lib/marked.min.js"></script>` to `sidebar.html`. The CSP nonce is correctly applied, but the relative path `lib/marked.min.js` is resolved by VS Code's webview as a `vscode-webview-resource://` URL — and **that URL is denied unless the path was first transformed via `webview.asWebviewUri(...)`**. The result is HTTP 403, `marked` is undefined, `marked.parse()` is never called on `chat-done`, the bubble's `innerHTML` is set to whatever the raw-text branch decided, and citations never become pills.

**Fix:** add a `{{MARKED_URI}}` placeholder in the HTML and a corresponding `webview.asWebviewUri(...)` substitution in `SidebarProvider.ts`, mirroring the existing `sidebar.js` / `sidebar.css` transforms.

**This becomes a permanent convention:** any new local resource added to `sidebar.html` must follow the same pattern. Logged in `memory/project_ai_engineering_decisions.md` entry 26.

## User Flows

### Flow 1: User opens DevNote sidebar (v0.5.1 first time)

Sidebar opens with Home tab active by default — Generate Doc + Recent Notes + Search input visible exactly as v0.4.x. No visual surprise for upgrade users.

### Flow 2: User clicks 💬 Chat tab (empty state)

Body morphs to chat layout: back button + "Chat" title at top, scroll region in middle showing 4 suggested-question buttons + empty state copy ("Ask anything about your past notes."), sticky chat input at bottom with disabled Send button.

### Flow 3: User clicks a suggested question

The clicked text fills `chatInput`, send fires automatically, the suggested-questions block hides, the user's question appears as a user bubble, the assistant bubble shows "Searching your notes…", then streams the answer.

### Flow 4: User types a custom question + sends

Same as Flow 3 minus the suggested-question click. Send button enables when input has text.

### Flow 5: 3-stage loading visible

Between user-clicks-send and first-token-arrives, the assistant bubble cycles through:
- "Searching your notes..." (during embed + retrieval, ~500ms-2s)
- "Found 5 notes..." (brief flash, ~150ms)
- "Generating answer..." (between retrieval-done and first-token-arrives, ~500ms-3s)

When first `chat-token` arrives, the bubble's content is replaced with that raw text and continues streaming.

### Flow 6: User clicks Stop mid-stream

The assistant bubble freezes at its current text. `[Note N]` markers remain plain (no pill swap on partial). Send button is restored. Python worker continues silently in the background; its eventual `done` is discarded.

### Flow 7: User clicks ← back button

Tab state returns to Home. Chat transcript and history are preserved (still in memory) — clicking 💬 Chat again shows the same conversation.

### Flow 8: VS Code restart

Chat history is in-memory only (D18 unchanged from v0.5.0). Fresh blank chat on restart.

### Flow 9: Citation pill click (now works correctly)

User sees properly rendered markdown answer with clickable `Note 1` pill (not literal `[Note 1]` text). Click → opens that note in the existing v0.3.0 historical-preview view (back from preview returns to chat).

## Error handling

### marked load failure (defensive — should not happen with the fix)

If `marked` is still `undefined` for any reason at `chat-done` time, the existing `typeof marked !== 'undefined'` guard from v0.5.0 Task 12 falls back to raw text rendering. Acceptable degradation.

### Stop button race conditions

User clicks Stop multiple times → idempotent (no-op after first click). User sends new query while old one is still "stopped" but Python is finishing → tracked by per-stream id; old stream's tokens can never reach a new bubble.

### Tab switching mid-stream

User clicks Home tab while chat is streaming → chat is paused visually (Home view shows). When user switches back to Chat tab, the streaming bubble continues filling (chat state is preserved across tab switches). Python and the assistant bubble's reference are unchanged.

### Suggested-question click race

Click happens before `chatInput` is wired → no-op (event listener checks element existence). After wired, click is handled identically to manual submit.
