# DevNote v0.5.0 — RAG Chat Design Spec

**Date:** 2026-04-26
**Status:** Draft (pending approval)
**Scope:** v0.5.0 only — final release of Phase 2 (AI memory arc)

---

## One-line summary

Add a chat surface to DevNote that lets developers ask natural-language questions about their past notes. Reuses v0.4.0's semantic retrieval as the **R** in RAG; adds **A**ugmentation via a grounded prompt template and **G**eneration via a streaming Gemini call. Answers render with inline clickable citation pills pointing back to source notes.

---

## The shift

**v0.4.0:** DevNote searches by meaning. Type "OAuth bug" → see ranked notes.
**v0.5.0:** DevNote **answers**. Type "what did I do with the OAuth bug last month?" → get a grounded answer with citations to the exact notes that support it.

This is the release where DevNote stops being *queryable memory* and starts being *conversational memory*.

---

## Decisions (D15–D21)

| # | Decision | Choice |
|---|---|---|
| D15 | Chat LLM model | Gemini 2.5 Flash primary + Flash-Lite fallback (reuse v0.2.0 cascade pattern) |
| D16 | Chat UI location | Stacked dual-input (search + chat) above the list region; mode shifts based on which input has content |
| D17 | Citation visibility | Inline clickable pills replacing `[Note N]` markers; click opens the source note in v0.3.0 preview |
| D18 | Conversation persistence | None — in-memory `ChatTurn[]` only; fresh chat on VS Code restart; "New chat" button to clear within session |
| D19 | Multi-turn strategy | Light multi-turn — last 4 turns of history sent in prompt; no LLM query rewriting; literal-query retrieval per turn |
| D20 | Markdown rendering | Plaintext stream (typewriter) + final `marked` render on completion |
| D21 | Retrieved notes count | Reuse v0.4.0 — k=5, threshold=0.70 (single source of truth across search + chat) |

Rationale and rejected alternatives are in the AI engineering decisions log entries #15–#21.

### Layered responsibility

| Layer | Owns | Doesn't know about |
|---|---|---|
| `worker.py` | Embed API, Gemini chat streaming, prompt-string transmission | SQLite, UI, conversation state |
| `PythonBridge.ts` | Subprocess transport + new streaming JSON-RPC framing | RAG semantics, chat history |
| `SearchService.ts` | Typed retrieval (unchanged from v0.4.0) | Chat, prompts, generation |
| `ChatService.ts` | Prompt template assembly, history management, citation validation, streaming orchestration | Subprocess details, UI rendering |
| `SidebarProvider.ts` | UI state machine, postMessage routing for streaming chunks | Python or RAG internals |
| Webview | Chat bubbles, token-by-token append, marked render at completion, pill swap, click handler | LLM, retrieval |

### ChatService API

```typescript
export interface ChatTurn {
  role: 'user' | 'assistant';
  text: string;
  citations?: Array<{ noteNumber: number; noteId: string }>;
}

export interface ChatStreamCallbacks {
  onChunk: (text: string) => void;
  onDone: (finalText: string, citations: Array<{ noteNumber: number; noteId: string }>) => void;
  onError: (err: Error) => void;
}

export class ChatService {
  private history: ChatTurn[] = [];

  constructor(
    private readonly searchService: SearchService,
    private readonly memoryStore: MemoryStore,
    private readonly bridge: PythonBridge,
  ) {}

  async askQuestion(query: string, callbacks: ChatStreamCallbacks): Promise<void>;
  clearHistory(): void;
  getHistory(): readonly ChatTurn[];
}
```

### PythonBridge streaming addition

Existing `call(method, params)` returns one Promise resolving to a single result.
New `callStream(method, params, onChunk)` invokes the worker, fires `onChunk(text)` for each `{type: "stream"}` message, and resolves the Promise when `{type: "done", final: <full text>}` arrives.

Wire protocol per turn:

```text
TS → Python: {"id": 1, "method": "stream_generate", "params": {"prompt": "..."}}
Python → TS: {"id": 1, "type": "stream", "text": "You "}
Python → TS: {"id": 1, "type": "stream", "text": "fixed "}
Python → TS: {"id": 1, "type": "stream", "text": "the OAuth bug..."}
Python → TS: {"id": 1, "type": "done", "final": "You fixed the OAuth bug..."}
```

Each `stream` chunk is appended to the webview transcript live. The `done` message triggers the final markdown render + citation-pill swap.

### Prompt template (the "A" in RAG)

```text
You are DevNote, a developer's memory assistant inside VS Code.
You help developers recall what they did in past work sessions.

Below are the top-{k} dev notes retrieved from the user's notebook,
ranked by semantic relevance. Each note has a title, date, and content.

CRITICAL RULES:
1. Use ONLY information from these dev notes.
2. Do NOT use general knowledge or training data.
3. Do NOT invent dates, code, names, or technical details.
4. If the answer is not in the notes, reply exactly:
   "I don't find that in your notes."
5. Cite sources inline as [Note N] where N is 1-{k}.
6. Use exact dates from notes — do not paraphrase as "last week".
7. Do NOT generate code unless quoting from a note.

{conversation_history_block}

--- Note 1 ---
Title: {title}
Date: {date}
Content:
{content_markdown}

--- Note 2 ---
...

User question: {query}

Answer:
```

Notes ordered weakest → strongest similarity (strongest last; "lost in the middle" mitigation per Lesson 3).

The `{conversation_history_block}` includes the last 4 turns when present. Skipped on turn 1 to save tokens (D19).

### Generation parameters (Gemini)

- `model`: `gemini-2.5-flash`
- `temperature`: `0.1` (anti-hallucination per Lesson 6)
- `max_output_tokens`: `1024`
- Fallback to `gemini-2.5-flash-lite` on 503 (overload) or 429 (quota) — same cascade pattern as v0.2.0 note generation
- `stream=True`

### Citation post-processing

After the stream completes, `ChatService` validates citations:

1. Regex match `\[Note (\d+)\]` against final text
2. Each captured `N` checked against `validNoteNumbers = {1..k}`
3. Map valid `N → noteId` (from the retrieved set passed to `ChatStreamCallbacks.onDone`)
4. Webview swaps each `[Note N]` text fragment for an `<a class="citation-pill" data-note-id="...">Note N</a>` element
5. Invalid `[Note 7]` (when k=5) renders as plain text — not clickable

## Data Model

### Schema (unchanged)

`schema_version` stays at 1. **No migration #2. No new tables. No `ALTER TABLE`.**

Rationale: D18 locked no persistence for chats. There is nothing new to store.

### MemoryStore additions (1 new query)

```sql
-- Fetch full note bodies for retrieved IDs (chat needs content_markdown, title, created_at)
SELECT id, title, content_markdown, created_at FROM notes WHERE id IN (?, ?, ?, ?, ?);
```

Implemented as `MemoryStore.getNotesByIds(ids: string[]): Promise<Note[]>`. v0.4.0's `searchQuery` returns `{id, score}` only; chat needs the full note body to build the prompt — this is the bridge.

### New TypeScript types

```typescript
export interface ChatTurn {
  role: 'user' | 'assistant';
  text: string;
  citations?: Array<{ noteNumber: number; noteId: string }>;
}

interface RetrievedNote {
  number: number;       // 1-based, position in retrieved list
  noteId: string;
  title: string;
  date: string;         // formatted YYYY-MM-DD for prompt clarity
  contentMarkdown: string;
  score: number;
}
```

### No new vector storage

Chat layer never touches embeddings directly. Retrieval is fully delegated to `SearchService.searchQuery` (v0.4.0). Chat operates on `RetrievedNote[]` returned via `MemoryStore.getNotesByIds(...)`.

## User Flows

### Flow 1: First-ever chat click (warm path — search has been used before)

```text
User types in 💬 chat input → "what did I do with OAuth?"
        ↓
SidebarProvider routes to ChatService.askQuestion(query, callbacks)
        ↓
ChatService:
  ├── searchService.ensureReady()      ← idempotent if already ready
  ├── searchService.searchQuery(query, 5) → top-5 IDs
  ├── memoryStore.getNotesByIds(ids)   → full note bodies
  ├── buildPrompt(query, notes, history=[]) → prompt string
  ├── bridge.callStream("stream_generate", {prompt}, onChunk)
  │       ↓ (per token)
  │       webview.postMessage({type: "chat-token", text: "..."})
  │       ↓ webview appends to current bubble (raw text)
  └── on done:
       ├── validate citations
       ├── webview.postMessage({type: "chat-done", final, citations})
       └── webview re-renders bubble: marked.parse + pill swap
        ↓
User sees: streaming typewriter → final rendered answer with clickable [Note N] pills
```

### Flow 2: First-ever chat click (cold path — search NEVER used)

Same as Flow 1, but `searchService.ensureReady()` triggers the **v0.4.0 onboarding flow**:
1. Python detection → install-guide popup if missing
2. Venv setup popup ("~30s")
3. Backfill popup if NULL embeddings exist
4. Then chat completes the question

**No new onboarding for chat.** Chat free-rides on v0.4.0's setup. If the user has never searched, their first chat is also their first search — same one-time setup, same pattern.

### Flow 3: Follow-up question (light multi-turn)

```text
User typed previously: "what did I do with OAuth?" → answered
User now types: "when was that?"
        ↓
ChatService.askQuestion("when was that?", ...):
  ├── searchService.searchQuery("when was that?", 5)  ← literal query (D19)
  ├── memoryStore.getNotesByIds(top5)
  ├── buildPrompt(query, notes, history=[turn1, ans1])  ← last 4 turns
  └── stream Gemini response
        ↓
LLM sees prior turn's answer → resolves "that" → cites date from same/related notes
```

If the literal "when was that?" retrieves only noise, the LLM either:
- Answers correctly anyway because the date is in the conversation history (e.g., `[Note 1]`'s date appeared in turn-1's answer), or
- Hits the refusal path: "I don't find that in your notes."

Both are acceptable v0.5.0 outcomes.

### Flow 4: User pivots topic mid-chat

```text
Turn 1: "what did I do with OAuth?" → answered
Turn 5: "what's the weather today?"
        ↓
Retrieval finds nothing above threshold OR finds OAuth-related notes (irrelevant)
        ↓
LLM hits refusal path: "I don't find that in your notes."
```

Graceful degradation. No crash, no hallucination, no stale topic continuation.

### Flow 5: Clearing the chat

User clicks the **New chat** button in the chat header → `ChatService.clearHistory()` → webview removes all bubbles → blank chat ready for new conversation. History list reset to `[]`.

### Flow 6: Empty chat input + ✕

User clicks ✕ on the chat input → input clears → mode shifts back to Recent Notes (or Search Results if search input still has content). Chat history persists in memory but is hidden until the user types in the chat input again.

### Flow 7: Click a citation pill

```text
User clicks [Note 3] pill in the answer
        ↓
Webview sends {type: "open-note", id: "<noteId>"}
        ↓
SidebarProvider calls existing v0.3.0 historical-preview flow
        ↓
List region morphs to Preview state showing the source note
        ↓
Back button returns to Chat mode with conversation intact
```

Citation click reuses 100% of v0.3.0's preview infrastructure. No new navigation surface.

### Flow 8: Streaming interrupted (error mid-stream)

If the Python worker crashes or Gemini errors mid-stream:
- Partial answer remains visible
- Toast: "Chat interrupted. Click to retry."
- "Retry" button re-runs the same query with fresh history

User's chat history is not corrupted. Failed turn is removed from `history` so retries don't re-send a half-answer.

### State transitions

```text
IDLE / Recent Notes ⇄ SEARCH ACTIVE ⇄ CHAT ACTIVE
         ⇅                ⇅              ⇅
       PREVIEW (historical, source state preserved)
```

Chat mode is a peer of Search mode — both are extensions of Idle, both share the morphing list region.

### Sidebar layout (chat active)

## Error Handling

### Guiding principle

> **Notion is authoritative. Memory is best-effort. Embedding is best-effort. Search is optional. Chat is optional.** Each new AI-layer failure lives one tier softer — never blocks essential layers.

### Error matrix (10 chat-specific modes)

| Error | Severity | User sees | Extension behavior |
|---|---|---|---|
| User has 0 notes | Edge case | Empty state in chat region: "Add a note first to start chatting." | Chat input disabled until first note synced |
| Retrieval finds 0 notes above threshold | Expected | "I don't find that in your notes." | LLM refusal path (correct outcome) |
| Gemini chat API 503 (overloaded) | Recoverable | Auto-fallback to flash-lite (silent if fallback succeeds) | Reuse v0.2.0 cascade |
| Gemini chat API 429 (quota) | Recoverable | Same fallback; if both fail → toast "Quota hit, try again later" | Don't store partial turn |
| Gemini chat API 5xx | Non-critical | Toast + retry button | Partial answer kept visible, removed from history |
| Network offline during chat | Expected | Empty state "Chat requires internet" | Recent Notes / Search still work |
| Worker crashes mid-stream | Non-critical | Toast "chat interrupted, retrying" | Auto-respawn + offer retry button |
| Invalid citation in LLM output (e.g. `[Note 7]` for k=5) | Soft warning | `[Note 7]` rendered as plain text (not clickable) | Logged via console.warn |
| LLM hallucination with valid citation | Hard to detect at runtime | Renders normally | Only catchable via eval set (v0.6+) |
| Streaming chunks arrive faster than render can handle | Performance | Brief lag, recovers | Webview batches DOM updates |

### Priority ladder (extended from v0.4.0)

```text
Generate / Sync flow:
  → Notion sync → Memory save → Embed (best-effort) → toast outcome

Chat flow (orthogonal to generate/sync):
  → ensureReady (reuses v0.4.0 setup) → retrieve → fetch bodies
  → stream LLM → render → validate citations → swap pills
  Each step has its own toast/refusal fallback; chat NEVER blocks generate/sync.
```

### What chat never breaks

- Note generation (`Ctrl+Alt+D`)
- Note sync to Notion
- Recent Notes browse
- Search (the search input + results UI is independent)
- Settings (no new chat-related settings introduced)

## Testing Strategy

### 1. Python worker tests — `python/tests/test_worker.py` (+5 tests)

Append to existing file. Covers:
- `stream_generate` happy path with mocked `client.models.generate_content_stream` returning a fake iterator
- Each chunk emits `{type: "stream", text}` followed by terminal `{type: "done", final}`
- Empty-stream edge case (zero chunks → just `done`)
- API error mid-stream → emits `{type: "error", message}` and worker stays alive
- Fallback model invocation (`flash` raises 503 → retry with `flash-lite`)

### 2. PythonBridge tests — `test/PythonBridge.test.cjs` (+2 tests)

Uses extended `mock_worker.py`. Covers:
- `callStream` invokes `onChunk` once per `stream` message and resolves on `done`
- `callStream` rejects on `error` message + cleans up internal state

### 3. ChatService tests — `test/ChatService.test.cjs` (~6 tests)

Mock `SearchService` + `MemoryStore` + `PythonBridge`. Covers:
- Prompt assembly contains all 7 critical rules + `{k}` substituted to retrieved count
- Notes ordered weakest → strongest in prompt body (lost-in-the-middle mitigation)
- History block omitted on turn 1, present from turn 2 onwards (last 4 turns max)
- `clearHistory()` empties internal array
- Citation validator strips `[Note N]` references where N > retrieved count
- `askQuestion` propagates streaming chunks to callbacks in order

### 4. Manual E2E checklist — `docs/reference/v0.5.0-test-checklist.md`

~50 checks: cold-start chat (no Python yet), warm chat, follow-up resolution, topic pivot refusal, citation pill click → preview, "New chat" reset, error recovery (kill worker mid-stream), VS Code restart loses chat (D18 verification), markdown render correctness on completion (D20), search and chat coexisting (D16).

### What we do NOT test in CI

- Real Gemini chat API calls (mocked in unit tests)
- Real LLM output quality (deferred to manual eval set in v0.6+)
- Hallucination rates (qualitative manual check before ship)
- Cross-platform chat streaming under flaky network (manual)

## What v0.5.0 is NOT

- NOT chat history persistence — fresh chat every restart (D18; full history deferred to backlog item #8)
- NOT user-selectable chat model — Flash + Flash-Lite cascade is hardcoded (deferred to backlog item #7)
- NOT progressive markdown rendering during stream — plaintext-then-render at completion (D20; progressive deferred to backlog item #9)
- NOT query rewriting for follow-ups — light multi-turn with literal-query retrieval (D19; full multi-turn possible in v0.6+ if eval shows need)
- NOT a reranker — single-stage retrieval is sufficient at our corpus size (Lesson 8)
- NOT HyDE / query expansion — direct query embedding only (Lesson 9)
- NOT a retrieval eval harness — manual qualitative checking before ship (Lesson 7; harness deferred to v0.6+)
- NOT a "chat over selected notes" mode — chat always retrieves freshly per turn
- NOT integration with Claude Code, Cursor, or other AI tools (deferred backlog: Add to Context, MCP server, CLI)
- NOT a separate chat webview panel — chat lives inside the existing sidebar (D16)
- NOT changes to v0.4.x search, generate, sync, settings, or recent-notes flows
